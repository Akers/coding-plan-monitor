## Context

本项目是一个全新的 Tauri 2.0 跨平台桌面应用（Windows 优先），用于监控多个 AI Coding Plan 供应商的额度使用情况。应用包含三个 UI 组件：悬浮面板（始终置顶显示额度）、配置窗口（管理供应商和面板设置）、系统托盘（快速操作入口）。

技术栈已确定：Tauri 2.0 + Vue 3 + TypeScript + Pinia + Vite。后端采用 Rust + TS 混合架构——Rust 负责系统级操作，TS 负责网络请求和业务逻辑。

当前无任何已有代码基础，从零构建。

## Goals / Non-Goals

**Goals:**

- 提供一个轻量（<10MB 安装包）、低资源占用的桌面额度监控工具
- 统一展示智谱、MiniMax、火山三个供应商的额度信息
- 悬浮面板不影响开发者日常工作流程（可吸附、可最小化、可穿透）
- 配置简单直观，支持 API Key 和 OAuth 两种鉴权方式
- 额度接近上限时主动通知，避免工作中断

**Non-Goals:**

- 不做历史额度数据分析和趋势图表
- 不做跨机器同步配置
- 不做供应商账号管理（注册、充值等）
- 不做网络代理配置（跟随系统代理）
- 不做自动切换供应商或自动降级策略
- 第一版不做 macOS/Linux 特有适配（仅确保可编译）

## Decisions

### 1. Rust + TS 混合架构而非纯 Rust 后端

**选择**：Rust 只做系统级操作（窗口、托盘、文件、吸附、OAuth 回调、通知、自启动），所有网络请求和数据解析在 TS 侧完成。

**理由**：
- 各供应商 API 差异大，TS 的 fetch + JSON 解析开发效率远高于 Rust 的 reqwest + serde
- 供应商适配器可能需要频繁调整（API 变化），TS 修改无需重编译 Rust
- Rust 侧代码量少，降低 Tauri IPC 桥接复杂度

**替代方案**：Rust 全权后端——类型更安全但对快速变化的 API 适配成本高。

### 2. 供应商适配器模式

**选择**：定义统一的 `ProviderAdapter` 接口，每个供应商独立实现。

**理由**：
- 各供应商 API 响应结构完全不同（智谱/火山需解析页面，MiniMax 有 REST API）
- 统一接口让面板层不关心供应商差异
- 新增供应商只需添加一个 TS 文件，无需改动其他模块

### 3. 额度数据按维度展示

**选择**：每个供应商返回多个 `UsageMetric`（如 5h 额度、周额度、月额度），面板按维度逐行展示进度条。

**理由**：
- 不同供应商的维度数量和名称不同（智谱/火山有 3 个进度条 + 1 行文字，MiniMax 有 4 个进度条）
- 统一为 `UsageMetric[]` 数组，面板可动态渲染

### 4. 进度条三级颜色阈值

**选择**：两级阈值（默认 50%、80%），将进度分为绿/黄/红三段。

**理由**：符合原始需求，两级阈值提供足够的视觉区分度，且用户可自定义阈值和颜色。

### 5. 配置文件使用 JSON

**选择**：`~/.config/coding-plan-monitor/config.json`，由 Rust 侧读写。

**理由**：
- 轻量，无需数据库
- 用户可直接手动编辑
- Tauri 的 `app_data_dir` 在各平台路径一致性好

### 6. OAuth 通过本地 HTTP 回调服务器实现

**选择**：Rust 在随机端口启动临时 HTTP 服务器，供应商 OAuth 重定向到 `http://localhost:<port>/callback`。

**理由**：
- 标准 OAuth 授权码流程
- 端口随机避免冲突
- 获取 token 后立即关闭服务器

### 7. 两个独立 Tauri 窗口

**选择**：悬浮面板和配置窗口作为两个独立的 Tauri 窗口，通过事件系统通信。

**理由**：
- 悬浮面板需要无边框、置顶、可穿透等特殊属性，与配置窗口的生命周期不同
- 独立窗口可独立显示/隐藏，互不干扰
- Tauri 的事件系统（`emit` / `listen`）天然支持跨窗口通信

## Risks / Trade-offs

- **[供应商页面结构变化]** → 适配器做容错解析，失败时显示错误标记而非崩溃；解析逻辑集中在 TS 侧便于快速修复
- **[OAuth 流程复杂度]** → 优先支持 API Key 方式，OAuth 仅作为不支持 API Key 供应商的备选方案；MiniMax 已有 API 可直接用 Key
- **[面板遮挡工作区]** → 提供吸附、最小化、点击穿透三种缓解机制；默认不穿透，用户按需开启
- **[跨 IPC 数据序列化]** → 额度数据量极小（每个供应商几百字节），IPC 开销可忽略
- **[Tauri 2.0 API 稳定性]** → 锁定 Tauri 2.0 稳定版，避免使用实验性 API
- **[Windows 优先策略]** → 使用 Tauri 抽象层减少平台特定代码，Linux/macOS 适配仅需处理托盘和自启动差异
